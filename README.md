## 1. Monorepo Architecture

The platform runs as a tightly coupled monorepo orchestrated through a single unified container:

```
├── .github/workflows/         # Event-driven GitHub Actions dispatch workflows
├── backend/                   # Platform Backend (Python / FastAPI / SQLAlchemy)
│   ├── alembic/               # Database migrations for teamwisedb
│   └── app/                   # Auth, RBAC, User Directory, Bridge APIs
├── enterprise/                # Enterprise Ingestion Backend (Node.js / Express / MySQL)
│   ├── sql/                   # Database init & seed scripts (timePayReview, teamwisedb)
│   └── src/                   # Play Store scraper, Chatbot poller, GitHub email client
├── ui/                        # Unified Frontend (React 19, TypeScript, Vite)
├── data/incoming-emails/      # Dedicated repository directory for dispatched emails
├── docker-compose.yml         # Single-command local & production stack
├── Dockerfile                 # Unified multi-stage runtime container
├── nginx.conf                 # Internal routing & reverse proxy
└── supervisord.conf           # Process supervisor managing all 3 services
```

### Core Roles of the Backends
- **Enterprise Backend (`enterprise/` - Node.js)**: Responsible for ingesting feedback from all external sources (Google Play Store, TimePay Chatbot, and event-based GitHub email dispatches) into MySQL `timePayReview`.
- **Platform Backend (`backend/` - FastAPI)**: Responsible for authentication, employee identity, RBAC access control, password security, and auditing in `teamwisedb`.
- **Frontend (`ui/` - React)**: Single-page application serving reviews triage, operational reports, directory hierarchy, and administration.

## 2. Ingestion Pipelines

| Source | Flow Type | Primary Trigger | Destination Table |
|---|---|---|---|
| **Google Play Store** | Polled & On-demand | Scheduled or `POST /api/ingestion/playstore/trigger` | `timePayReview.review` |
| **TimePay Chatbot** | Polled & On-demand | Scheduled or `POST /api/chatbot/poll` | `timePayReview.chatbot_sessions` & `review` |
| **Incoming Emails** | Event-Driven & Smart Polling | GitHub Dispatch `email-received` -> Commit to Repo -> Smart Polling | `timePayReview.review` & `filtered_emails` |

### Smart Email Ingestion
1. Email arrives in Microsoft 365 / Outlook.
2. Power Automate triggers a GitHub `repository_dispatch` event (`email-received`).
3. GitHub Actions workflow commits the JSON payload to [`data/incoming-emails/`](data/incoming-emails).
4. The Node.js enterprise backend polls repository commits:
   - **Commit SHA Caching**: Exits immediately if the latest commit SHA on the email folder has not changed.
   - **Dynamic Poll Interval**: Starts at 30 seconds, backs off to 180 seconds when idle, and immediately resets to 30 seconds upon new activity.
   - **SHA-256 Deduplication**: Hashes message IDs and content to prevent duplicate records.

## 3. Quick Start & Execution

### Prerequisites
- Docker & Docker Compose (v2.20+)
- Or Node.js 20+ & Python 3.12+ (if running bare-metal)

### Running with Docker (Recommended)

1. **Configure Environment Variables**:
   ```bash
   cp .env.example .env
   ```

2. **Start the Unified Stack**:
   ```bash
   docker compose up --build
   ```

3. **Access Services**:
   - Web Platform: [http://localhost:8080](http://localhost:8080)
   - Platform API Docs: [http://localhost:8080/api/v1/health](http://localhost:8080/api/v1/health)
   - Enterprise API: [http://localhost:8080/api/health](http://localhost:8080/api/health)
   - Direct Backend: [http://localhost:8000](http://localhost:8000)
   - Direct Enterprise: [http://localhost:3000](http://localhost:3000)

---

### Running Manually for Local Development

#### 1. Databases (MySQL 8.4)
```bash
docker run -d --name finai_mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=password \
  -e MYSQL_DATABASE=teamwisedb \
  -e MYSQL_USER=teamwise \
  -e MYSQL_PASSWORD=password \
  -v $(pwd)/enterprise/sql/01_init_schema.sql:/docker-entrypoint-initdb.d/01_init_schema.sql \
  -v $(pwd)/enterprise/sql/02_seed_data.sql:/docker-entrypoint-initdb.d/02_seed_data.sql \
  mysql:8.4
```

#### 2. Platform Backend (FastAPI)
```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

#### 3. Enterprise Ingestion Backend (Node.js)
```bash
cd enterprise
npm install
npm test
npm start
```

#### 4. Frontend UI (React + Vite)
```bash
cd ui
npm install
npm run build
npm run dev
```

## 5. Security & Reliability Highlights

- **Strict Multi-Database Isolation**: `teamwisedb` handles HR and credentials; `timePayReview` stores operational tickets. Neither table leaks data to the other.
- **PII Redaction**: Email addresses, credit card numbers, phone numbers, and SSNs are masked before persisting review text.
- **Directory Traversal Protection**: Upload paths and filenames are validated against strictly resolved base directories.
- **Strict Parameterized Queries**: All SQL statements use parameter bindings; dynamic order clauses are strictly whitelisted against an explicit enum list.
- **Rate Limiting & Lockouts**: Brute-force protection on authentication routes with configurable failure windows.
